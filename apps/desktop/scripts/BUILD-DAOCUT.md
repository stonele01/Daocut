# Daocut Windows build

Use Windows x64, Node 22.18 or newer, and the pnpm version named in the root package.json. Install the frozen workspace dependencies, then build:

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
node apps/desktop/scripts/prepare-daocut-runtime.mjs
node apps/desktop/scripts/build-daocut.mjs
```

The runtime preparation downloads the checksum-pinned FFmpeg/FFprobe build from src/ffmpeg-runtime.mjs, its license/source notice, and the Chromium revision selected by the locked Playwright package. The default location is apps/desktop/.release/runtime/win-x64. Preparation refuses an existing output folder; reuse it in later builds, or pass --runtime=<new folder> to prepare another one. A partial download can be retried into a different folder. Keep these inputs inside this checkout on D:.

The default output is apps/desktop/.release/win-x64/out/win-unpacked/Daocut.exe. Existing builds get a new timestamped folder and are not overwritten. Keep the complete win-unpacked directory together. Use --nsis for a per-user installer whose destination the employee can choose.

The build downloads the Electron version selected by pnpm-lock.yaml through electron-builder. For a local offline build, explicitly supply --runtime=<existing runtime> and --electron-source=<matching Electron application folder>. That folder is only read. Its Electron runtime is copied into the build without the old application, updater or integrity record. Caches remain under .release/cache.

Production dependencies are staged with pnpm deploy --prod --no-optional --ignore-scripts; pnpm 10+ also uses --legacy. The stage gets the current desktop sources, core/server sources and both built UIs. The Chromium revision must match the deployed Playwright version.

Pass --company-profile=<absolute JSON path> for an employee release. The profile must contain only name, serverUrl and caPem strings; serverUrl must be an HTTPS origin without a path. caPem is empty for a publicly trusted certificate, or contains the single public self-signed service certificate generated by setup-lan (not an arbitrary CA bundle). Private keys, employee tokens and unknown fields are rejected. A validated copy is included as resources/company-profile.json, and staged product.company.required is true. Without a profile, company.required is false; this is useful for source-development builds, not the employee release workflow.

Automatic updates are off unless --updates=<HTTPS base> is explicitly provided. An update-enabled build requires --nsis. The generic Windows feed is <HTTPS base>/win/x64. The feed URL cannot contain credentials, query parameters or fragments. No GitHub token is bundled. The updater's dedicated Electron session trusts the imported service certificate only for its exact host, matching certificate bytes, valid dates and hostname/IP. Other hosts retain system trust. Actual update downloading still needs validation in the company environment. See the [company release guide](../../../docs/DAOCUT-COMPANY-RELEASE.md) for publishing the output to the LAN server.

The artifact uses Daocut / Daotian / com.daotian.daocut. It includes THIRD_PARTY_NOTICES.md copied unchanged from packages/daocut/THIRD_PARTY_NOTICES.md, containing the original editor's MIT copyright and permission notice, plus the FFmpeg notices. The separate application LICENSE files are excluded by the company packaging configuration; their notice is retained in THIRD_PARTY_NOTICES.md. The executable's icon, product/company names and embedded ASAR integrity are verified after packaging. Do not replace app.asar inside a finished build.

After source-only changes, --resume=<previous .release build folder> reuses its production dependency stage and produces a new out-<timestamp> directory. Rebuild both UIs first. Dependencies changed: use a fresh stage instead. The script never installs, launches or publishes the app, and never changes the installed app's data.
