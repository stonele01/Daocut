# 大视频打开优化 · 0.2.54

后续播放恢复改动见 [0.2.55 记录](DAOCUT-PLAYBACK-0.2.55-20261115.md)。

旧流程在建立个人工程前对整条视频计算 SHA-256。对于网络盘上的大视频，该步骤耗时很长，界面也缺少真实进度。

- 新建的大素材引用使用明确标记的 sampled-sha256-v1：结合文件大小，对包含首尾的八个均匀位置各读取 1 MiB。小于等于 8 MiB 的素材仍计算完整 SHA-256。
- 身份缓存按算法及文件版本区分；并发打开共用读取，重启后可复用有效缓存。一次操作内复用已核实的路径。
- 对话框显示检查目录、查找工程、识别视频、打开工程、读取已有分析等步骤；识别阶段显示真实读取量，打开阶段显示耗时。
- 已有个人工程、已发布共享分析保持原身份算法。旧版完整身份在没有缓存的新电脑上仍可能需要一次完整读取，期间显示真实进度。
- 工程备份和恢复继续使用完整 SHA-256 校验，同时保留编辑素材指纹，确保恢复后的个人修改、方案及分析仍对应原素材。

采样指纹用于编辑素材识别，不能替代文件完整性校验。方案参考 [Kdenlive 素材哈希实现](https://raw.githubusercontent.com/KDE/kdenlive/master/src/bin/projectclip.cpp)，本次八点 SHA-256 为独立实现。
